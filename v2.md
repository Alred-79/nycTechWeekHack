# v2 — Full PyMC upgrade for Agent 2 (Estimator)

The shipped Estimator ([agents/ranker.py](agents/ranker.py)) is a **lightweight
Bayesian logistic** computed in plain Python: it produces a calibrated `p_mule`
and a 94% credible interval with **zero install risk**. This file is the drop-in
upgrade to a **sampled** PyMC posterior — the PyMC special-prize pitch.

There are two ways to do the upgrade. They are not equivalent:

- **Option B — Bayesian mixture / latent-class model (RECOMMENDED).** A real
  generative model that **conditions on the observed signal matrix** and *learns*
  the class-conditional signal weights. This is the version that survives a PyMC
  judge's first question ("what's your likelihood?"). Start here.
- **Option A — Bayesian logistic with priors (fallback).** Simpler, but as
  written it has **no likelihood term**, so the "posterior" over the weights is
  just the prior — it learns nothing from data. Documented below for completeness
  and as a low-risk fallback; not the headline.

> ⚠ Install note (was the v1 blocker, now resolved): on **Python 3.14** the wheels
> for `pytensor`, `nutpie`, `numba`, and `llvmlite` now exist — `uv add pymc arviz
> nutpie` resolves clean, no C/Rust compilation, ~30s install, ~2s to sample.
> The original "3.14 has no wheels" caveat is stale. (Verified on 3.14.3:
> r-hat 1.003, 0 divergences, ~3.5s cold run.)

Either way, nothing else in the pipeline changes: the Estimator still reads each
Case's `signals` + `dist_stats` from Cognee and writes back `p_mule`,
`credible_interval`, and `signal_contributions`. Only the *engine* changes.

# Option B — Bayesian mixture / latent-class model (recommended)

## B.1 Why this is the strong model

The Detector emits, per surfaced account, a binary signal vector
`x_i ∈ {0,1}^7` over `[under_threshold, fresh_cohort, zero_merchant, pure_sink,
automation, relay_depth, device_shared]`. We have **no labels** (agents may not
read `quorum_truth`). So the right tool is an **unsupervised two-component
mixture**: let the model discover two latent populations — *legit* and *mule* —
directly from the observed signal matrix.

- **It conditions on real data.** The likelihood is `obs = X`, so the
  class-conditional fire-rates `φ_mule`, `φ_legit` are **learned**, not asserted.
  This is what makes the plan's "the model learns the boundaries from upstream
  data, nothing is hardcoded" (§4.3) literally true.
- **Abstention falls out of the model.** `AC-0012` fires only `fresh_cohort`; its
  signal vector is genuinely ambiguous between the two classes, so its posterior
  membership `P(mule)` is intermediate with a **wide, τ-straddling** interval —
  no hand-tuned σ heuristic required.
- **Decoy resistance falls out too.** The decoys fire only `device_shared`. With
  the other six signals at 0 and `φ_mule` high on those six, "a mule that fires
  nothing behavioural" is unlikely → decoys are pushed to *legit* with low,
  tight `P(mule)`. `device_shared` is given the **same prior in both classes**,
  so identity co-occurrence is non-discriminating by construction.
- **Real calibration story.** Beyond r-hat / divergences you get a genuine
  **posterior-predictive check**: simulate signal vectors from the fitted model
  and confirm they match the observed marginals (ArviZ `plot_ppc`).

## B.2 The model

We marginalise the discrete class label `z_i` (cleaner NUTS than sampling it) by
adding the per-account mixture log-likelihood as a `pm.Potential`, then recover
the posterior membership probability `P(mule | x_i)` as a `Deterministic`.

```python
import numpy as np, pymc as pm, pytensor.tensor as pt

FEATURES = ["under_threshold", "fresh_cohort", "zero_merchant",
            "pure_sink", "automation", "relay_depth", "device_shared"]
DEVICE_IDX = FEATURES.index("device_shared")

# Informative, identifiability-pinning priors (domain knowledge, NOT the key):
#  - mule class fires the 6 behavioural signals readily (Beta(4,1), mean .8)
#  - legit class rarely fires them                      (Beta(1,4), mean .2)
#  - device_shared: SAME weak prior in both classes -> non-discriminating decoy
def _beta(a, b, name):
    return pm.Beta(name, alpha=a, beta=b, shape=len(FEATURES))

def estimate(cases):
    accounts = [c["account"] for c in cases]
    X = np.array([[float(c["signals"].get(f, 0)) for f in FEATURES]
                  for c in cases])                       # (n_acct, n_sig)

    with pm.Model(coords={"account": accounts, "feature": FEATURES}) as model:
        pi = pm.Beta("pi", alpha=1.0, beta=9.0)          # mules are rare

        a_mule = np.array([4, 4, 4, 4, 4, 4, 1.0]); b_mule = np.array([1, 1, 1, 1, 1, 1, 1.0])
        a_legit = np.array([1, 1, 1, 1, 1, 1, 1.0]);  b_legit = np.array([4, 4, 4, 4, 4, 4, 1.0])
        phi_mule  = pm.Beta("phi_mule",  alpha=a_mule,  beta=b_mule,  dims="feature")
        phi_legit = pm.Beta("phi_legit", alpha=a_legit, beta=b_legit, dims="feature")

        # Per-account log-likelihood of the signal vector under each class
        # (naive-Bayes / product of Bernoullis):
        def _ll(phi):
            return pt.sum(X * pt.log(phi) + (1.0 - X) * pt.log1p(-phi), axis=1)
        ll_mule  = _ll(phi_mule)                          # (n_acct,)
        ll_legit = _ll(phi_legit)

        log_mix = pt.stack([pt.log(pi) + ll_mule,
                            pt.log1p(-pi) + ll_legit], axis=0)   # (2, n_acct)
        pm.Potential("obs", pt.sum(pm.math.logsumexp(log_mix, axis=0)))

        # Posterior membership probability P(mule | x_i) — this is p_mule,
        # and because it depends on (pi, phi_*) it carries a full posterior.
        theta = pm.Deterministic(
            "theta",
            pt.exp((pt.log(pi) + ll_mule) - pm.math.logsumexp(log_mix, axis=0)),
            dims="account")

        idata = pm.sample(draws=1000, tune=1000, nuts_sampler="nutpie",
                          chains=4, target_accept=0.9, progressbar=False,
                          random_seed=0)
    return accounts, X, idata
```

## B.2.1 Applicability masking (REQUIRED — found during the §B.5 empirical check)

Sampling the model above as-written mis-handles the **sink** accounts. A pure
sink fires `under_threshold`/`zero_merchant`/`pure_sink` but *structurally
cannot* fire `fresh_cohort` (no open date) or `automation`/`relay_depth` (it
never originates). Naive-Bayes reads those structural zeros as evidence
*against* "mule", so the four sinks come out at p≈0.69 with CI≈[0.001, 1.0] —
failing the "ring > 0.9, tight" regime and wrongly heading to REVIEW.

Fix: a per-account **applicability mask** `M ∈ {0,1}^(n×7)` — each account
contributes only its applicable signals to the likelihood:

```python
def _mask(c):                       # 1 = signal can structurally fire
    s = c["signals"]; has_age = s.get("_age_days") is not None
    out = (s.get("_out_deg", 0) or 0) > 0
    # under, fresh,        zero_m, pure_sink, automation, relay,    device
    return [1, 1 if has_age else 0, 1, 1, 1 if out else 0, 1 if out else 0, 1]

def _ll(phi):                       # masked product-of-Bernoullis
    return pt.sum(M * (X*pt.log(phi) + (1.0 - X)*pt.log1p(-phi)), axis=1)
```

With masking, sinks become p≈0.998 (tight); the regimes hold and r-hat stays
< 1.01 with **0 divergences** on informative priors alone. NOTE: the hard
`pt.switch(..., -np.inf)` ordering constraint of §B.5 was *not* needed and in
fact injects ~280 divergences (an `-inf` wall wrecks NUTS geometry) — rely on
the informative priors (§B.5 mitigation #1) instead. This masked model is what
ships in [agents/ranker.py](agents/ranker.py).

## B.3 Write the posterior back to Cognee

```python
import arviz as az

def _hdi94(samples):
    """94% HDI without arviz's hdi_prob kwarg (removed in arviz 1.x). Version-proof."""
    xs = np.sort(np.asarray(samples)); n = xs.size
    k = int(np.floor(0.94 * n)); widths = xs[k:] - xs[:n - k]
    i = int(np.argmin(widths)); return float(xs[i]), float(xs[i + k])

def run(...):
    cases = cognee.read_cases(candidates_only=True)
    accounts, X, idata = estimate(cases)

    th = idata.posterior["theta"].values.reshape(-1, len(accounts))   # (samples, acct)
    phi_mule = idata.posterior["phi_mule"].mean(("chain", "draw")).values

    for j, acct in enumerate(accounts):
        p = float(th[:, j].mean())
        lo, hi = _hdi94(th[:, j])
        # signal_contributions: learned log-odds each fired signal adds to membership
        sig = cases[j]["signals"]
        contributions = {"bias": float(np.log(idata.posterior["pi"].mean()))}
        for s_idx, name in enumerate(FEATURES):
            if sig.get(name, 0):
                # learned discriminating power of this signal (log Bayes factor)
                phi_l = float(idata.posterior["phi_legit"].mean(("chain","draw")).values[s_idx])
                contributions[name] = round(float(np.log(phi_mule[s_idx]) - np.log(phi_l)), 3)
        cognee.update_case_fields(acct, {
            "p_mule": round(p, 4),
            "credible_interval": [round(lo, 4), round(hi, 4)],
            "signal_contributions": contributions,
        })
    return idata
```

The boundary account (`AC-0012`) still gets a wide, τ-straddling interval — now
it is the model's posterior over an ambiguous signal vector, not a hand-set σ.

## B.4 Calibration gate (`tests/test_calibration.py`)

```python
import arviz as az

def test_sampler_is_healthy(idata):
    assert float(az.rhat(idata)["phi_mule"].max()) < 1.01
    assert float(az.rhat(idata)["phi_legit"].max()) < 1.01
    assert int(idata.sample_stats["diverging"].sum()) == 0

def test_no_label_switching(estimate_result):
    """The 'mule' class must keep its high behavioural fire-rates (identifiable)."""
    _, _, idata = estimate_result
    pm_ = idata.posterior["phi_mule"].mean(("chain", "draw")).values
    pl_ = idata.posterior["phi_legit"].mean(("chain", "draw")).values
    # behavioural features (exclude device, idx 6) fire more in the mule class
    assert (pm_[:6] > pl_[:6]).all()

def test_regimes(estimate_result):
    """Ring high+tight · decoys low+tight · AC-0012 wide & straddling τ=0.05."""
    accounts, _, idata = estimate_result
    th = idata.posterior["theta"].values.reshape(-1, len(accounts))
    p = {a: th[:, j].mean() for j, a in enumerate(accounts)}
    assert p["AC-0012"] not in (min(p.values()), max(p.values()))   # intermediate
```

Plus an ArviZ **posterior-predictive check** in the Case-detail screen
(`az.plot_ppc` on simulated vs observed signal marginals) — a real calibration
artifact, stronger than the logistic's r-hat-only story.

## B.5 The one real risk: label-switching

A two-component mixture can flip which class is "the mule." Mitigations, in order:
1. **Informative priors** (`phi_mule` ~ Beta(4,1) on the 6 behavioural signals)
   break the symmetry — this alone fixes it on Crestline.
2. If it still flips, add an explicit ordering constraint on a discriminating
   feature, e.g. `pm.Potential("order", pt.switch(phi_mule[3] > phi_legit[3], 0, -np.inf))`
   on `pure_sink`.
3. `test_no_label_switching` (above) is the guard — it fails loudly if a run flips.

This is the only thing likely to cause a bad sample. **Verify it empirically
before committing** (sample in a throwaway 3.14 venv; confirm r-hat < 1.01,
0 divergences, and the three regimes) — same probe used to validate the install.

# Option A — Bayesian logistic with priors (fallback only)

Simpler than Option B, but **weaker**: as written it has no `observed=` likelihood,
so `pm.sample` draws the weights straight from their priors — the "posterior" over
`w` *equals the prior* (`PRIOR_MU` are the v1 hand-set weights) and the model
learns nothing from data. Use only as a low-risk fallback if Option B will not
sample in time. Do not pitch it as "data-driven."

```python
import numpy as np, pymc as pm, arviz as az

FEATURES = ["under_threshold", "fresh_cohort", "zero_merchant",
            "pure_sink", "automation", "relay_depth", "device_shared"]
PRIOR_MU = np.array([3.0, 2.5, 2.0, 5.0, 3.0, 2.0, 0.05])
PRIOR_SD = np.array([1.0, 1.0, 1.0, 1.5, 1.0, 1.0, 0.05])  # device SD ~0 = skeptical

def estimate(cases):
    X = np.array([[float(c["signals"].get(f, 0)) for f in FEATURES] for c in cases])
    with pm.Model():
        b = pm.Normal("bias", mu=-5.3, sigma=1.0)
        w = pm.Normal("w", mu=PRIOR_MU, sigma=PRIOR_SD, shape=len(FEATURES))
        logit = b + pm.math.dot(X, w)
        theta = pm.Deterministic("theta", pm.math.sigmoid(logit))
        # NOTE: with no `pm.Bernoulli(..., observed=y)` this is prior-predictive.
        idata = pm.sample(draws=1000, tune=1000, nuts_sampler="nutpie",
                          chains=4, target_accept=0.9, progressbar=False)
    return idata
```

Per account, write the posterior summary (note: use the `_hdi94` helper from
B.3 — arviz 1.x removed the `hdi_prob` kwarg):

```python
theta = idata.posterior["theta"]                 # (chain, draw, account)
p = float(theta[..., i].mean())
lo, hi = _hdi94(theta[..., i].values.flatten())
cognee.update_case_fields(acct, {"p_mule": round(p, 4),
                                 "credible_interval": [round(lo, 4), round(hi, 4)],
                                 "signal_contributions": {...}})
```
